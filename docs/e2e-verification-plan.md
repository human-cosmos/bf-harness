# Bugfix Harness V1 全页面端到端验证主线

## 1. 目标与范围

本文档是「完整端到端验证（包含所有页面功能的测试验证）」的测试主线。验证覆盖当前 Web UI 的全部路由页面、任务工作流主链路、自由对话链路、系统设置与错误状态，以及后端 API 与页面的联动。

验证遵循「逐条执行、发现 BUG 立即修复、修复后复验通过再继续」的闭环。每条验证项都给出：验证内容、验证方式、验收标准、通过条件。

## 4. 逐条验证明细

### E2E-01 基础与导航

- 验证内容：后端健康检查、前端可渲染、全局导航项、文档标题。
- 方式：`curl` 健康检查 + 浏览器访问首页与各顶级路由。
- 验收标准：健康检查返回 `ok:true`；首页能渲染项目列表；顶部导航可跳转。
- 通过条件：所有响应 200；页面无运行时报错（无 console error）。

### E2E-02 项目列表 `/`

- 验证内容：空态、项目卡片（名称/路径/任务数/待办数）、搜索过滤、删除项目二次确认。
- 方式：创建多个项目后访问首页；用标题/ID/状态搜索；点击删除并确认。
- 验收标准：项目卡片信息与 API `/api/projects/summary` 一致；搜索过滤生效；删除后列表刷新且后端记录删除。
- 通过条件：删除有二次确认，确认后项目消失；无孤儿记录。

### E2E-03 添加本地项目 `/projects/new`

- 验证内容：名称/路径必填校验、目录选择、验证命令编辑、允许/禁止路径。
- 方式：打开表单，提交空表单看校验；填写有效本地 Git 仓库保存。
- 验收标准：非法输入被前端校验拦截并提示；合法输入创建成功并跳转首页；重启后项目仍在。
- 通过条件：保存后首页出现新项目；`/api/projects` 返回对应记录。

### E2E-04 添加远程项目

- 验证内容：远程 URL 表单、host/凭据/分支字段、克隆任务状态。
- 方式：填写远程 URL 提交；轮询 `/api/projects/remote/:jobId`。
- 验收标准：无效 URL 校验；有效 URL 启动克隆 job；job 终态成功或可读失败信息。
- 通过条件：job 状态机正确，不产生僵尸项目记录。

### E2E-05 项目任务 `/projects/:id`

- 验证内容：项目信息、任务列表（标题/ID/状态/时间）、删除任务。
- 方式：进入项目页，创建任务后查看列表；删除任务。
- 验收标准：任务列表与 `/api/tasks?projectId=` 一致；删除后任务消失。
- 通过条件：删除有确认；worktree 与记录被清理。

### E2E-06 待办中心 `/pending`

- 验证内容：待办聚合展示、跳转到对应处理页。
- 方式：创建处于待审批/待验收的任务，进入 `/pending`。
- 验收标准：出现对应待办条目；点击跳转到正确页。
- 通过条件：跳转目标正确，无空指针。

### E2E-07 新建任务 `/tasks/new`

- 验证内容：问题描述等必填字段校验、多行字段解析、创建后生成 1.0 契约并进入 DRAFT。
- 方式：空提交看校验；填全提交；断言跳转 `/tasks/:id` 且 API 状态为 DRAFT。
- 验收标准：必填校验生效；契约 `schemaVersion=1.0`；创建后 DRAFT。
- 通过条件：页面跳转正确；`/api/tasks/:id` 返回 DRAFT 与契约。

### E2E-08 任务详情 `/tasks/:id`

- 验证内容：状态徽章、工作流步骤、任务说明、开始修复/开始实施按钮、删除任务、实时事件。
- 方式：对 DRAFT 任务查看详情；点击开始修复；查看事件流。
- 验收标准：状态/步骤/下一动作正确；按钮触发 API；事件流可见。
- 通过条件：下一动作与 workflow-model 一致；重复点击不重复创建 runtime。

### E2E-09 修复计划 `/plan`

- 验证内容：计划摘要、向 AI 追问、批准、批准并实施、退回并重新分析。
- 方式：让任务进入 WAITING_FOR_PLAN_APPROVAL 后操作三个按钮。
- 验收标准：批准后进入 IMPLEMENTING；批准并实施触发实施；退回回到 ANALYZING；退回意见被记录。
- 通过条件：状态机正确，操作有确认弹窗，无代码修改泄漏。

### E2E-10 操作审批 `/approvals`

- 验证内容：待处理审批列表、风险等级展示、单个接受/拒绝、批量拒绝。
- 方式：制造高风险操作审批；单个决定；批量决定。
- 验收标准：决定调用正确 API，审批记录更新；拒绝会中断流程。
- 通过条件：决定后列表刷新；状态与后端一致。

### E2E-11 变更与检查 `/diff`

- 验证内容：文件状态、行号 Diff、验证命令运行、失败后继续修复。
- 方式：任务有 diff 后查看；运行检查；构造失败验证继续修复。
- 验收标准：Diff 解析正确（新增/删除/上下文行号）；验证结果记录退出码/输出；失败提示继续修复。
- 通过条件：验证通过后进入 WAITING_FOR_ACCEPTANCE；失败最多自动修复 2 轮后 BLOCKED。

### E2E-12 验收报告 `/report`

- 验证内容：生成报告、验收条件、技术细节、通过/退回再改/不采用。
- 方式：WAITING_FOR_ACCEPTANCE 任务生成报告后做三个决定。
- 验收标准：报告关联 diff 与验证结果；通过→ACCEPTED；退回→继续实施；不采用→REJECTED。
- 通过条件：终态正确，报告字段完整。

### E2E-13 运行日志 `/logs`

- 验证内容：日志列表、级别/来源/阶段筛选、增量加载。
- 方式：对有日志的任务打开日志页，切换筛选。
- 验收标准：日志与 `/api/tasks/:id/logs` 一致；筛选生效。
- 通过条件：无渲染错误，空态可读。

### E2E-14 系统设置 `/settings`

- 验证内容：Agent/模型/安全/项目默认值/存储/远程/Runtime 各组编辑与保存、提示词模板保存与恢复、磁盘诊断、Codex Runtime 检测与手动指定。
- 方式：修改并保存一组设置；恢复默认；修改提示词；查看诊断。
- 验收标准：保存后 `/api/settings` 返回更新值；恢复默认生效；诊断展示正确；Runtime 显示可用。
- 通过条件：数据持久化（刷新后仍在），校验非法值拦截。

### E2E-15 自由对话列表 `/chat`

- 验证内容：对话列表、新建对话、空态。
- 方式：进入项目对话页，新建对话。
- 验收标准：列表与 `/api/projects/:id/conversations` 一致；新建跳转详情。
- 通过条件：新建后详情可打开，输入框可见。

### E2E-16 自由对话详情

- 验证内容：发送消息、策略面板、文件引用搜索、快捷指令、工具链操作（fork/压缩/中断/重命名/归档）。
- 方式：打开对话，使用输入框与工具栏，验证各操作调用对应 API。
- 验收标准：消息发送返回 turnId；策略保存生效；文件搜索返回结果；快捷指令打开对应面板；fork/压缩/中断/重命名/归档可用。
- 通过条件：UI 与 API 一致，错误可读。

### E2E-17 错误状态

- 验证内容：404 页面、未知任务加载失败。
- 方式：访问不存在路由与不存在任务 ID。
- 验收标准：404 显示返回链接；未知任务显示加载失败。
- 通过条件：不白屏、不崩溃，提示可理解。

### E2E-18 真实 AI 端到端主链路

- 验证内容：创建任务→开始修复（分析）→计划批准→开始实施→验证→生成报告→验收通过。
- 方式：使用 fixture 本地 Git 仓库与可执行的 `echo` 验证命令，走真实 Codex Runtime。
- 验收标准：任务依次经历 DRAFT→ANALYZING→WAITING_FOR_PLAN_APPROVAL→IMPLEMENTING→VALIDATING→WAITING_FOR_ACCEPTANCE→ACCEPTED。
- 通过条件：最终 `ACCEPTED`，主仓库干净，worktree 有产物。

### E2E-19 重启恢复

- 验证内容：服务重启后项目、任务、对话仍存在，未完成状态可继续。
- 方式：创建数据后重启前后端，访问各列表。
- 验收标准：记录仍在 SQLite；页面可加载；未完成状态不自动续跑原 Thread。
- 通过条件：无孤儿进程，无监听端口残留。
